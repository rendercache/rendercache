## Accepted product and scope

Self-hosted, warm, logged HTML pre-render cache for public JavaScript apps. Humans receive the ordinary origin app. The completed prototype will pre-warm sitemaps, serve snapshots to bots, keep stale copies during refresh, detect empty shells and show delivery records. One Go binary plus externally installed Chrome/Chromium; later container bundles the browser. Lightpanda, BareProxy integration, hosted billing, framework plugins and PDFs are deferred.

Cold requests will proxy immediately and enqueue work, never wait for a browser. Expired hits will serve the saved copy and deduplicate refreshes. Refresh hooks preserve a usable old copy until replacement succeeds. Serving a response does not prove indexing or AI citation; user-agent matching is a claim, not authentication.

## Known limits and design decisions

Storage durability verified on Linux; directory fsync on other operating systems is not verified. Each render starts a fresh browser for isolation; pooling is deferred. Asset origins are explicit and POST-driven data loading/cross-origin document frames are outside the current path. Default settling does not guarantee readiness: configure a real selector. Captures do not flatten shadow roots/iframes and are not a security sanitizer. Keep future demo previews sandboxed.

The browser loads origin URLs directly. An app using location.host sees the origin host; configure its public/canonical base URL correctly. Stored HTML links are not rewritten. Stored outcomes now include HTML, redirects and 404/410. Other non-200 statuses are transient errors except 401/403, which withdraw shared copies. The guard is an application control, not a replacement for OS egress/container isolation.

Session-three operational limits: the scheduler tick is up to 1s when idle. Discovery errors retry with capped backoff no slower than the configured discovery interval. A removed sitemap entry is unscheduled but its file is not deleted; an already running retired job can finish writing its old file. Cache counts reflect successful load/save, not an audit on every status read. Whole discovery can be ready with an empty page set; always inspect discovered counts. Config requires refresh/discovery intervals at least 1s and retry base at least 100ms to avoid tight loops. Byte limits are per document, with a whole-scan time limit rather than a total cross-document byte budget. Default limits bound the page set; further resource hardening is session 6.

Session-four operational policy: snapshot_ttl and warm_interval are independent. Stale responses have no maximum-stale cutoff. Extra request entries have no eviction during process lifetime (default 256), separate from sitemap memory; disk quotas/cleanup remain session 6. A full allowance rejects unknown purges with 429 and cold URLs still proxy. Warm=false still serves saved/stale records without refreshing. Purge always requires a configured token, including loopback; with no token it returns 503. Cached replies are private/no-cache downstream, not CDN-immutable. Retired worker state is bounded by work in flight. Sitemap counters include structured cached responses, not only 200 HTML. Positive privacy suppression is retained until a successful public render.

Session-five limits: raw diagnostics and saved snapshots can be captured at different times, so editorial changes can look like missing JavaScript content. Text extraction approximates visibility and does not evaluate CSS/layout or all languages. Diagnostic errors never delete saved copies. The admin UI reads local snapshots and fetches the configured public origin; it is not a public arbitrary-URL renderer. No automatic shell audit/index is persisted. Log recent lists/counters are process-local; files append across restart. A successful response write is not a remote read acknowledgement. Receipts are best-effort, not fsync/audit-grade; crash/failed writes may leave a partial final line. One process must own each data directory. A stuck OS filesystem call can leave the single writer pending until process exit, while admission and shutdown waiting are bounded. Stderr lifecycle timeouts may leave at most two pending writes until exit. The UI is on the separate admin listener; use HTTPS/tunneling for remote Basic/bearer credentials and never forward unauthenticated loopback admin routes publicly. Query strings are omitted from delivery logs but path segments may still be sensitive. Do not claim user-agent verification or indexing/citation proof.
