RenderCache's first Apache 2.0 alpha: a self-hosted, warm HTML pre-render cache for public JavaScript apps, with crawler delivery receipts and a protected “What the bot sees” comparison page.

Linux amd64 binary archive and SHA-256 checksums are attached. Chrome/Chromium is an external dependency for the standalone binary; the Dockerfile installs it. This is an alpha for evaluation, not a production-readiness claim. Download the matching tagged source for Docker, nginx and Cloudflare examples.

The release pipeline verifies race-enabled Go tests with real Chrome, a non-root Chromium container under resource/filesystem limits, nginx routing, Cloudflare request logic, deterministic archive rebuilding, checksums and the extracted executable. The isolated container test explicitly disables Chrome's sandbox; the image itself keeps the sandbox enabled by default and fails closed if the host does not support it. Deploying the sandbox-enabled image on your host still requires verification.

Known limits include one process per data directory; in-memory queue/retry state; no automatic snapshot eviction (quota pressure needs explicit prune or larger limits); best-effort delivery logs; approximate shell diagnostics; no universal crawler identity/indexing guarantee; no shadow-root/iframe flattening; direct-origin location.host semantics. HTTP proxy requests, including upgrades, have a configured total deadline. The Cloudflare Worker example is request-tested and has not been deployed to a live zone. Container images are built/tested by CI, not published to a registry in this release. See README and deployment guide for exact controls and limits.
